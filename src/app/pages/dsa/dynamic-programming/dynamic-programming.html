Dynamic Programming - Lecture 1

When to use DP, the two conditions, Memoization vs Tabulation, Fibonacci O(2^n) to O(n).

HTML notes for Complete Dynamic Programming - DP Series - Lecture 1. Core idea: plain recursion repeats the same work, DP stores it and reuses it. Flow: recursion tree -> find repeats -> store answers -> reuse.

  • DP = recursion + cache. Same logic, no repeated calls.
  • Roadmap: when to use DP, 2 conditions, Fibonacci proof, 2 styles.
  • Future videos add patterns (knapsack, LCS, LIS, grid DP) here.
One-line summary: same subproblem twice in the tree means remember it, do not recompute it.

Ask two questions before DP. If either is NO, DP is the wrong tool.

Condition 1 - Overlapping Subproblems

  • Memorize: same subproblem solved many times in recursion.
  • Fibonacci proof: fib(5) calls fib(4) and fib(3). But fib(4) calls fib(3) again. So fib(3) runs twice, fib(2) runs three times.
  • Interview line: draw tree, circle repeat, say overlapping confirmed.

Condition 2 - Optimal Substructure

  • Memorize: optimal whole answer built from optimal smaller answers.
  • Fibonacci proof: fib(n) = fib(n-1) + fib(n-2). Exact smaller answers combine into exact big answer.
  • Counter-example: longest simple path in general graph. Reusing a sub-path can form a cycle, so DP fails there.

Checklist before code

  1. Define state: dp[i] = answer for input i.
  2. Check repeats: sketch tree for n = 5.
  3. Write recurrence: dp[i] = dp[i-1] + dp[i-2].
  4. Set base cases: dp[0] = 0, dp[1] = 1.
  5. Pick Memoization or Tabulation.
  • Memoization = top-down + cache. Keep recursion, check cache on entry, store before return. Only visited states solved. Risk: stack depth.
  • Tabulation = bottom-up + table. Loop from base cases upward. All states solved in order. No stack overflow, easy O(1) space.
  • Same speed: O(n) states x O(1) work = O(n).

Memoization (top-down)

function fibMemo(n: number, memo: Record<number, number> = {}): number {
  if (n <= 1) return n;
  if (memo[n] !== undefined) return memo[n];
  memo[n] = fibMemo(n - 1, memo) + fibMemo(n - 2, memo);
  return memo[n];
}

Tabulation (bottom-up)

function fibTab(n: number): number {
  if (n <= 1) return n;
  const dp: number[] = [0, 1];
  for (let i = 2; i <= n; i++) {
    dp[i] = dp[i - 1] + dp[i - 2];
  }
  return dp[n];
}

Memorize: F(0)=0, F(1)=1, F(n)=F(n-1)+F(n-2). Naive tree visibly repeats.

Why naive is O(2^n)

  • Each call spawns 2 children. Depth n gives about 2^n nodes.
  • fib(5) = 15 calls. fib(40) = about 331 million calls.

Naive (do NOT ship)

function fibNaive(n: number): number {
  if (n <= 1) return n;
  return fibNaive(n - 1) + fibNaive(n - 2);
}

Why DP is O(n)

  • Unique states: n+1 values (0..n). Each computed once.
  • Work per state: one addition, O(1).
  • Formula: time = states x work = O(n) x O(1) = O(n).
  • n = 5 table: dp = [0, 1, 1, 2, 3, 5]. Answer dp[5] = 5.
  • Numbers: n=10: 177 vs 10. n=20: 21,891 vs 20. n=30: 2.7M vs 30. n=40: 331M vs 40.

Best: O(n) time, O(1) space

function fibBest(n: number): number {
  if (n <= 1) return n;
  let prev2 = 0, prev1 = 1;
  for (let i = 2; i <= n; i++) {
    const cur = prev1 + prev2;
    prev2 = prev1;
    prev1 = cur;
  }
  return prev1;
}
