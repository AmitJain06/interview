Backtracking

CHOOSE → EXPLORE → UNDO · generate all permutations, subsets, combinations · LeetCode 46 & 78

Backtracking = depth-first search over a decision tree, where every path is explored and then systematically "undone" so the next branch starts from a clean state. It is the standard tool for "generate all …" problems: permutations, subsets, combinations, N-Queens, Sudoku, word search.

  • State — the partial answer built so far (e.g. current = [1,2]).
  • Decision at each node — pick the next candidate (e.g. the next unused element).
  • Recursion — descend one level per decision, stop when the base case is reached.
  • Undo — remove the last choice before trying the next candidate (the magic step).
One-line summary: go deep, save answers, walk back, try the sibling branches — until every branch has been explored.

The prompt uses "all" / "every" / "generate" together with arrangements or choices:

  1. "Return all permutations" → n!, choose any unused element at each level.
  2. "Return all subsets / combinations" → 2ⁿ / nCr, include-or-skip each element.
  3. "Return all ways / all valid boards / all paths" → constraints checked at each node (N-Queens, Sudoku, word search).
  4. As soon as a branch can never lead to a valid answer, prune it (cut it early) instead of exploring it.

Backtracking vs DP — quick contrast

  • DP answers "what is the best / the count / the ways" and reuses overlapping subproblems.
  • Backtracking "list every concrete solution" — the tree usually has no repeated nodes (n! or 2ⁿ leaves).
StepWhat it does
CHOOSEPick the next candidate and add it to the current state.
EXPLORERecurse one level deeper with the updated state.
UNDORemove the candidate again so the next iteration starts clean.
Interview line: "Every backtracking solution is a recursion inside a for-loop: add → recurse → remove."

Start with current = [] and, at every level, choose any unused element. A complete permutation appears when all 3 positions are filled — that is the base case.

  • Choices per level: 3 → 2 → 1 — that shrinking branch count is exactly how you count n! = 3! = 6.
  • Each LEVEL of the tree = one position of the permutation.
  • Leaves are the only nodes worth saving — a permutation must use all elements.
  • current and used are shared objects — every recursive branch mutates the same lists/arrays.
  • Without UNDO, the next for-iteration starts from a polluted state: [1,2] stays [1,2,3] instead of becoming [1,3].
  • Without UNDO, used stays true forever → no element can ever be reused by a sibling branch.
  • Restoring the state = "backtracking" — the behaviour the whole technique is named after.

Every backtracking problem reduces to this shape. Change only the base case and the choose/undo lines.

Generic template

void Backtrack(...)
{
    if (condition)              // BASE CASE: answer complete
    {
        // save a COPY of the current state
        return;
    }

    for (candidate of choices)   // try every option
    {
        // CHOOSE  — apply the candidate
        // EXPLORE — recurse deeper
        // UNDO    — revert the candidate
    }
}
  • Save a copy, never the shared current object (it mutates after the return).
  • Sum of first-n recursion: the loop + recursion runs over the whole tree in DFS order.
  • For permutations add used[]; for subsets/combinations track a start index instead.

Interview note: n = 10 → 10! = 3,628,800 permutations. This pattern is only practical for small n (usually n ≤ 8–10).
  1. Decision tree — nodes are partial answers, edges are choices, leaves are full answers.
  2. CHOOSE → EXPLORE → UNDO — the three-step cycle inside every for-loop + recursion.
  3. Base case — condition that saves the answer and returns (permutation is complete / sum reached).
  4. Pruning — skipping a branch early when it can never be valid (e.g. N-Queens attack check).
  5. used[] / start index — the two ways to keep answers distinct (permuations vs subsets/combinations).
  6. Shared state — one current object reused by all branches; correct only because of UNDO.
Summary: backtracking = recursion in a for-loop that tries every choice, goes deep, saves completed states, and always undoes the last choice before trying the next.
